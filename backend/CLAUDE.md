# Backend instructions (`backend/`) — Service Topology & Registry Platform

The root `CLAUDE.md` still applies; specs are in `docs/backend/`.

## Commands (run in `backend/`)
- `make check` — gofmt check, `go vet ./...`, `go test ./...` (unit, conformance, lifecycle). The Makefile uses `go` from PATH, else `/usr/local/go/bin/go`; override with `GO=...`.
- `make dev-up` — local MongoDB 8.0 as a single-node replica set (needs `secrets/mongodb_root_password.txt`; see `docs/backend/LOCAL_DEVELOPMENT.md`). Memory is capped for a 2 GB Rancher Desktop VM.
- `make db-ui` — optional mongo-express web UI on `http://127.0.0.1:8081` (user `root`, password from `secrets/`).
- `make test-integration` — tests against MongoDB; each uses and drops a temporary database.
- `make run` — API on `HTTP_ADDR` (default `:8080`) against the local database.
- `make seed` — load the mock fixture (idempotent replace); `make validate` — validate it without a database; `make schema-check`.
- `make import-flows FILE=… [FORMAT=native|bpmn] [MAPPING=…]` — import business flows (ADR-022; examples in `fixtures/flows/`).
- Never pass the database password on a command line: use `scripts/mongosh.sh` (authenticates inside the container from the secret file) or `make db-shell` (prompts).
- Shared fixtures are generated by the frontend: `cd apps/web && npm run fixtures:update` after changing the mock or validation rules; both test suites then check them.
- Validation is a port of `apps/web/src/domain/validation.ts`; change both together and regenerate fixtures.

## Rules

- Follow `docs/backend/SOURCE_ALIGNMENT.md`; do not silently redefine product behavior.
- Implement the existing contract `docs/api/openapi.json` and schemas in `docs/schemas/`; the validation rules and codes match `apps/web/src/domain/validation.ts`. Change the contract only together with the frontend types and contract tests.
- Backend language: Go. Architecture: modular monolith with REST/OpenAPI.
- MongoDB is the sole authoritative database (root ADR-019, ADR-DB-004; it replaced ArcadeDB). Do not add another database, graph projections, or cross-database synchronization without a user-approved architecture decision record.
- Keep domain types independent from HTTP and MongoDB driver packages. Use repository/query interfaces and stable application IDs.
- One collection per canonical entity kind with `_id` = the stable ID; relationships are documents in `relationships` (`docs/backend/PERSISTENCE.md`). Convert documents through `bsonjson.go` (never Extended JSON). Use typed driver filters with input only as values; no `$where`, JavaScript, or query strings; constant collection and field names.
- Do not expose database-internal identifiers (ObjectIds) or `_meta` bookkeeping through the API.
- Preserve mock-first delivery and explicit mock/observed/simulated provenance.
- Never confuse infrastructure containment with runtime communication dependencies.
- Preserve the 2D topology as the primary operational view; 3D galaxy is a secondary visualization. Do not put renderer-specific layout/camera state into resource identity.
- Bound graph traversal depth, result count, query time and authorization scope.
- Implement only the requested backend milestone (B1–B8). Commit it with scope `b1`…`b8`; do not push unless asked. Add tests and update docs for behavior changes. Do not claim tests passed unless executed.
- Treat 250 visible nodes, 750 visible edges and navigation across 1,000 entities as benchmark targets, not guarantees.
- Confirm MongoDB edition and licensing (Community Server is SSPL) and deployment constraints before production commercialization.
